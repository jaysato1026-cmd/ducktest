# PHPtoSHELL 支援與故障處理手冊

版本：2026.10.28｜適用：PHPtoSHELL 觀察模式與 Windows Firewall 操作

## 先判斷狀態

1. 先看 Dashboard 的健康文字：`運作正常`、`取樣逾時`、`發生錯誤`。
2. 確認「上次連線取樣」不是 `等待資料`，並按一次「立即更新」。
3. 來源表格空白代表目前沒有被取樣到的 TCP 8080 來源，不代表 PHP/Tomcat 已停止。
4. 封鎖按鈕不能用時，先看狀態列與「操作紀錄」；不得為了測試停用防毒或降低 PowerShell 執行政策。

## 常見狀況

| 狀況 | 判斷 | 處理 |
|---|---|---|
| `防火牆待檢查` | 尚未通過 Check 或不是管理員 | 先按 Firewall 檢查；保留錯誤文字與時間 |
| `取樣逾時` | 觀察工作超過 30 秒未更新 | 檢查主機負載、PowerShell、NetTCPConnection 權限；不要直接開自動封鎖 |
| 表格空白 | 沒有目前的 Established 8080 來源 | 從合法內網來源執行已核准的業務連線，再按立即更新 |
| 來源被誤判 | 白名單或 NAT 未涵蓋實際出口 IP | 先暫停自動模式，確認來源與 NAT，再由人工更新白名單 |
| 封鎖後服務異常 | 來源規則可能擋住合法出口 | 立即解除本工具建立的規則；保留事件與 journal，完成業務回歸後才重新評估 |
| HTTP Guard 失敗 | 上游、TLS、串流或限制不相容 | 回到原入口，保留測試結果；Pilot 不得直接對外上線 |

## 支援資料包

只收集以下不含密碼、Cookie、token、POST 內容或私鑰的資料：版本、`release-manifest.json`、事件 JSONL 的已脫敏副本、Dashboard 健康摘要、Windows Firewall Check 錯誤文字、以及目標服務的產品版本。打包前人工檢查來源 IP、主機名與客戶資料；需要外部支援時先遮罩。

## 回復原則

使用本工具建立的規則才可由本工具解除；不得匯入整份舊防火牆設定。若 GUI 無法啟動，使用受控管理員 PowerShell 依 journal 的精確規則名稱回復，並保留命令輸出。回復完成後以合法來源驗證管理登入、播放器更新、發布與排程，再記錄結果。

## 升級門檻

連續兩次觀察逾時、事件檔無法寫入、規則狀態無法驗證、或 PHP/Tomcat 出現錯誤時，停止自動封鎖並升級給系統管理員。PHP2SHELL 相關告警需保留原始日誌證據、確認實際 Web worker 版本，並優先採用供應商修補版本；不要把 `memory_limit=-1` 當成完整修復。
