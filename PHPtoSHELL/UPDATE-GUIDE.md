# PHPtoSHELL 更新與驗證

版本：2026.10.28。更新器已完成套件預檢、WhatIf 與隔離合成檔案更新測試；真實執行中 EXE 的更新、中斷復原與撤回尚未驗收。

追加本機證據：使用 `-InstallDirectory` 指向暫存隔離目錄，以合成 EXE 檔案完成一次實際更新，確認政策、事件與舊 EXE 備份內容保留。這不涵蓋真實執行中 EXE、更新中斷、撤回或現場安裝。

降版拒絕亦已在隔離目錄實測：已安裝版本高於套件版本時，更新器以失敗結束，現有 EXE 內容保持一致，且不建立更新備份。連續更新會建立不同的備份目錄，舊版 manifest 與 EXE 一併保留。

Windows 檔案鎖定測試已通過：以 Windows 檔案控制代碼禁止舊 EXE 被覆寫／刪除，更新失敗後，舊 EXE 與舊 manifest 的位元組均維持原樣。目前七項更新測試通過。此情境發生於替換前，尚未覆蓋 EXE 替換成功後 manifest 寫入失敗的回復分支，也不等同真實執行中程式的完整更新驗收。

後續故障注入已覆蓋替換後回復：測試包成功替換 EXE 後，測試包裝器令 manifest 複製拋出錯誤；實際更新器回復分支將舊 EXE 與舊 manifest 還原至原始位元組。八項更新測試通過。這只驗證可捕捉的寫入錯誤，未涵蓋斷電、程序被強制終止或回復時磁碟故障。

## 驗證交付包

在解壓後的 PHPtoSHELL 資料夾，用 Windows PowerShell 執行：

```powershell
.\Verify-PHPtoSHELL.ps1 -Path .
.\Update-PHPtoSHELL.ps1 -Package . -WhatIf
```

將下載套件解壓到獨立資料夾，再執行驗證與更新預覽。套件資料夾不能與安裝資料夾相同；出現 `Package and installation directories must be different.` 時，請移至另一個解壓位置後重新預覽。`-InstallDirectory` 可指定隔離測試位置；不要指向磁碟根目錄。

驗證器的 `HASH-OK` 表示檔案符合包內清單。`SIGNED` 表示 Windows 簽章檢查通過；仍須核對發行者是否符合組織信任。`UNSIGNED-TEST` 表示確認沒有簽章。`UNKNOWN` 表示簽章檢查不可用，不能解讀為已確認未簽章。`INVALID` 表示缺檔、雜湊或簽章有問題，停止使用該套件。

WhatIf 只顯示版本、安裝目的地與預計備份位置，不會建立備份或安裝檔案。出現 `WHATIF: no files changed.` 才代表預檢成功；這不能證明實際更新或回復能成功。

本機測試已確認：對不存在的隔離安裝目錄執行 WhatIf 後，該目錄仍不存在。更新測試目前共有六項，涵蓋此無寫入情境、降版拒絕、連續更新備份、政策／事件保留、竄改檔案、缺檔與異常路徑。

## 已驗證的拒絕情境

EXE 雜湊不符、清單檔案缺失或清單含路徑穿越時，更新器會以失敗結束。包內清單與檔案同時被改寫仍可能通過雜湊檢查；正式發布需要可信簽章與來源驗證。

## 實際更新前的剩餘門檻

在隔離安裝目錄驗證舊版到新版更新、既有政策與事件保留、執行中 EXE 鎖定、磁碟不足、中途失敗及撤回。現有更新腳本沒有完整自動撤回交易；備份目錄存在也不等於已具備可驗收的回復功能。

在完成以上測試前，先使用解壓後的 EXE 作受控測試。更新檢查無法證明目標 PHP/Tomcat 相容性，亦不會將 HTTP Guard 自動接入現場流量。
